# مصفوفة الاختبارات وبوابات القبول — الإصدار الأول

**التاريخ:** 2026-11-02  
**الحالة:** معيار قبول إلزامي؛ حالات الاختبار لا تعد ناجحة إلا بوجود نتيجة تشغيل فعلية مرتبطة بـ commit وworkflow run أو تقرير جهاز قابل لإعادة الإنتاج.

## 1. قواعد الإثبات

- كل اختبار يحمل ID ثابتًا ويحدد الطبقة والنتيجة المتوقعة.
- لا يكتب PASS دون مخرجات فعلية ومرجع commit/Run.
- اختبارات PostgreSQL تثبت invariants قاعدة البيانات؛ اختبارات API تثبت حدود HTTP والتفويض؛ اختبارات Flutter تثبت سلوك العميل المحلي؛ واختبارات الأجهزة تثبت التشفير والتخزين الحقيقي.
- الاختبار الوهمي أو fake server لا يساوي اختبار جهازين متصلين بخادم PostgreSQL.
- لا يساوي نجاح CI الوثائقي اجتياز بوابة تشغيلية.

## 9. بوابات إيقاف الإطلاق

يمنع الانتقال للإطلاق إذا تحقق أي مما يلي:
- فرق غير مفسر بين دفتر القيود والأرصدة.
- وصول غير مصرح به لعلاقة أو مرفق.
- فقد أو تكرار عملية مالية بعد retry أو restore.
- إمكانية تعديل أو حذف قيد منشور دون reversal/audit.
- اعتماد عملية من منشئها خلاف السياسة.
- كشف عملية محلية غير متزامنة على أنها معتمدة.
- تشفير محلي أو استعادة مفتاح غير مثبتين على جهاز مستهدف.
- عدم نجاح استعادة نسخة احتياطية ومطابقة الدفتر.

## 10. حالة الاختبارات الحالية

هذه المصفوفة معيار مستقبلي وليست تقرير نجاح. الاختبارات الموجودة مثبتة في `PROJECT_STATUS_AND_NEXT_STEPS_AR.md` مع أرقام PR وCI. العناصر غير المثبتة تظل Pending حتى تقدم أدلة تشغيلية.

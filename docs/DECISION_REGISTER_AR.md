## 2. عقد المزامنة الأساسي

### Envelope
كل عملية محلية تحمل على الأقل:
- `operation_id`: UUID/ULID عالمي ثابت.
- `actor_user_id` و`device_id`: من هوية موثقة، لا من payload موثوق.
- `relationship_id`.
- `operation_type` و`schema_version`.
- `client_created_at`: معلومة تشخيصية لا ترتيب مرجعي.
- `base_server_version`.
- `payload` و`request_hash`.
- `dependency_operation_ids` عند الاعتماد على عمليات سابقة.
- `attachment_refs` عند وجود مرفقات.
- `local_status`.

### دورة الإرسال
1. حفظ العملية وoutbox ذريًا محليًا.
2. إرسال الدفعات مع operation ID وhash نفسهما في كل retry.
3. تحقق الخادم من الهوية والجهاز والعضوية والصلاحية والنسخة والمراجع والقواعد المالية.
4. حفظ inbox/idempotency والعملية والقرار/القيد والحدث ورقم النسخة في معاملة خادمية واحدة.
5. إعادة نتيجة canonical تشمل operation ID والحالة والنسخة وserver sequence ووقت الخادم.
6. تعليم outbox synchronized فقط بعد حفظ الاستجابة canonical محليًا.
7. سحب أحداث العلاقة بعد آخر cursor؛ كشف sequence gap وطلب replay.
8. تطبيق كل event مرة واحدة عبر inbox محلي idempotent.

### حالات المزامنة
`local_only`, `queued`, `sending`, `synchronized`, `retryable_error`, `blocked_dependency`, `conflict`, `rejected_by_server`.

### نتائج الخادم
`accepted`, `already_processed`, `needs_approval`, `conflict_stale_version`, `forbidden`, `invalid_reference`, `dependency_pending`, `schema_unsupported`, `idempotency_mismatch`.

لا تستخدم Last-Write-Wins أو client timestamp للفصل في أي مبلغ أو موافقة أو ترتيب دفتر.

## 3. قواعد المرفقات

- تحفظ bytes في object storage أو قناة ملفات منفصلة، لا داخل PostgreSQL.
- يحتفظ الخادم بالـ metadata: attachment ID، relationship ID، operation ID، uploader، MIME، size، SHA-256، upload state.
- لا يقبل ربط مرفق بعلاقة أخرى.
- upload قابل للاستئناف والتحقق من hash؛ لا يعلن اكتمال المرفق قبل تحقق الخادم.
- الوصول يتطلب عضوية وصلاحية في العلاقة، ويكون عبر رابط مؤقت أو stream مفوض.
- لا تحتوي سجلات التطبيق على روابط دائمة أو أسرار وصول.

## 4. قرار التعارض والتزامن

- أول قرار نهائي صحيح commit على الخادم هو القرار canonical.
- القرار الثاني على expected version قديم يعاد conflict ولا يغير الأول.
- إعادة إرسال العملية نفسها بنفس ID/hash تعيد النتيجة المخزنة.
- إعادة استخدام ID مع hash مختلف ترفض وتسجل كحدث أمني.
- العمليات التابعة لا تعالج قبل اعتماد مراجعها؛ تعاد dependency_pending أو تبقى queued.
- لا يعتمد أي ترتيب مالي على client clock.
